# MultiSelectLookup

A Power Apps Component Framework (PCF) control that adds a **multi-select lookup** to
Dataverse / Model-Driven forms. Users pick several records from a searchable dropdown;
each choice is shown as a removable tag, and the selection is persisted to the bound
column as a delimited list of record ids.

## Features

- Tag-based input with per-tag remove buttons
- Search-as-you-type with debouncing (server FetchXML + instant client-side filtering)
- Checkbox option list with **Select all** / **Clear results** / **Clear all**
- Full keyboard support: `Enter` / `Space` / `↓` to open, `↑` `↓` to navigate,
  `Enter` to toggle, `Backspace` to remove the last tag, `Esc` to close
- Resolves pre-selected ids to readable names on load (batched `in` queries)
- Required/disabled states, error message, accessible roles and `aria-*` wiring
- No runtime dependencies — plain React plus the control's own CSS

## Properties

| Property | Type | Notes |
| --- | --- | --- |
| `Selected items` | string | **Bound field.** Delimited list of record ids. |
| `Entity name` | string | Table to look records up from, e.g. `account`. |
| `Display attribute` | string | Attribute shown as the record label, default `name`. |
| `Primary id attribute` | string | Falls back to the form context `PrimaryIdAttribute`. |
| `Entity set name` | string | Optional OData entity set override. |
| `Label text` / `Placeholder text` | string | Empty label hides the label row. |
| `Selected items delimiter` | string | Default `;`. |
| `Maximum options` | number | Default `100`. |
| `Allow search` / `Show select all` | boolean | Feature toggles. |
| `Disabled` / `Required` | boolean | Host states. |
| `Error message` | string | Overrides the required message. |

### Outputs

- `value` — the delimited list of selected ids, written back to the bound field.
- `selectedRecords` — comma separated ids, for use in rules and formulas.

## How the value is stored

Dataverse lookup columns hold a single guid, so bind this control to a **text or memo**
column. Ids are stored as `id1;id2;id3`. Parsing is tolerant of whitespace, `{ }` and
`( )` wrapping, duplicates, and custom delimiters.

## Prerequisites

- Power Apps CLI (`pac`) and the Power Apps SDK (`pcf` CLI)
- Node.js 18+ (Node 22+ recommended — the test suite uses the built-in test runner)

## Build, test, deploy

```bash
npm install          # @microsoft/pcf-core is a build-time-only dependency
npm run build        # pcf build  -> out/controls/MultiSelectLookup
npm test             # 45 unit + interaction tests, no bundler required
npm run watch        # pcf start, for local host debugging

pac pack             # build the solution .zip
pac deploy --pacpac build/Solution_1_0_0_0.zip
```

## Tests

`npm test` runs the pure helpers *and* the real control class. Because the control cannot
be constructed outside the Power Apps host, `test/stubs/` provides:

- `pcfCore.ts` — a minimal `@microsoft/pcf-core` stand-in (`ComponentBase`, `React`)
- `hooks.mjs` / `register.mjs` — ESM hooks that alias that module and let Node resolve the
  project's extensionless relative imports

These are test-only and are never bundled into the control.

## Notes and limitations

- The control renders its own required-field error. A custom PCF control cannot set the
  host form's native *"This field is required"* state; for that, also mark the bound column
  as required in Dataverse so the form blocks the save itself.
- The OData entity set is taken from the form context metadata when available, then falls
  back to naive pluralisation. Set `Entity set name` explicitly for tables where neither is
  correct (for example some `new_*` custom tables).
- Search uses a `like` filter on the display attribute and fetches at most `Maximum options`
  rows — it is not a full server-side paged search.
